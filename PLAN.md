# MacNexus — Development Plan

**Версія:** 0.1.0  
**Статус:** Active Development  
**Платформа:** macOS, Apple Silicon  
**Мова:** Python 3.12  
**GUI:** PySide6  
**Тестування:** unittest  
**Статичний аналіз:** Ruff

---

## 1. Призначення

MacNexus — локальний застосунок для моніторингу Mac, аналізу дискового простору та безпечного обслуговування системи.

Основні принципи:

- Local-first: обробка даних локально.
- Privacy-first: відсутність передачі даних на зовнішні сервери.
- Safety-first: захист системних файлів.
- Manual control: жодних операцій видалення без підтвердження.
- Modular architecture: незалежні модулі та сервіси.
- Testability: автоматизовані тести основної логіки.

| Компонент | Технологія |

## 3. Основні модулі

### 3.1 Dashboard

- Інформація про Mac та macOS.
- Використання RAM.
- Використання дискового простору.
- Автоматичне оновлення показників.
- Візуальні попередження при високому використанні ресурсів.

### 3.2 File Scanner

- Сканування вибраних директорій.
- Отримання метаданих файлів.
- Визначення розмірів файлів і папок.
- Обробка помилок доступу.
- Фільтрація результатів.
- Скасування сканування.

### 3.3 Disk Analyzer

- Аналіз використання дискового простору.
- Групування файлів за категоріями.
- Відображення найбільших директорій.
- Візуалізація результатів сканування.

### 3.4 Large Files

- Пошук великих файлів.
- Сортування за розміром.
- Фільтрація за типом і розміром.
- Перехід до розташування файлу.

### 3.5 Duplicate Finder

- Пошук потенційних дублікатів.
- Попередня перевірка за розміром.
- Порівняння за SHA-256.
- Групування однакових файлів.

### 3.6 Cleanup

- Аналіз тимчасових і кеш-файлів.
- Перегляд знайдених об'єктів перед очищенням.
- Підтвердження кожної операції.
- Переміщення до системного Trash.
- Захист критичних системних директорій.

### 3.7 Settings

- Налаштування теми.
- Налаштування поведінки сканування.
- Керування параметрами застосунку.

## 4. Архітектура

Проєкт поділяється на три основні частини:

**UI**
- Вікна.
- Сторінки.
- Віджети.
- Стилі.

**Services**
- Отримання системної інформації.
- Сканування файлової системи.
- Аналіз результатів.
- Виконання дозволених операцій.

**Models**
- Структури даних.
- Результати сканування.
- Інформація про файли.

Правила:
- Не розміщувати бізнес-логіку у віджетах.
- Не перевантажувати MainWindow.
- Кожен сервіс повинен мати окремі тести.
- Не додавати залежності без практичної потреби.

## 5. Безпека

- Не змінювати оригінальні файли під час сканування.
- Не видаляти файли автоматично.
- Не сканувати системні директорії без необхідності.
- Обробляти відмови в доступі без аварійного завершення.
- Не переходити за symlinks без визначеної політики.
- Перед видаленням показувати точний шлях і розмір об'єкта.
- За можливості використовувати системний Trash замість безповоротного видалення.

## 9. Правила розробки

1. Працювати послідовно, невеликими кроками.
2. Перед змінами перевіряти поточний стан файлів.
3. Не переписувати робочі модулі без необхідності.
4. Спочатку реалізовувати логіку, потім інтегрувати її в UI.
5. Для кожного сервісу створювати тести.
6. Після кожного етапу запускати Ruff, форматування та всі тести.
7. Не додавати функції, які не потрібні поточному етапу.
