# MacClear — Development Plan

**Тип продукту:** Mac Maintenance Suite  
**Версія документа:** 1.0  
**Статус:** Initial planning  
**Ціль:** MacClear 1.0 MVP  
**Платформа:** macOS, Apple Silicon M1–M5  
**Мова розробки:** Python 3.12  
**GUI:** PySide6  

---

## 1. Концепція проєкту

MacClear — локальний застосунок для аналізу, очищення та обслуговування macOS.

Основне призначення — допомогти користувачеві контролювати використання дискового простору, знаходити непотрібні файли, дублікати та великі файли, аналізувати стан системи й безпечно виконувати очищення.

### Основні принципи

- Local-first: обробка даних локально на комп'ютері.
- Privacy-first: не передавати інформацію про файли на зовнішні сервери.
- Manual control: жодного автоматичного видалення без підтвердження.
- Safety-first: захист системних каталогів і критичних файлів.
- Transparency: користувач бачить, що саме буде змінено.
- Modular architecture: функціональність розподілена між незалежними модулями.
- Testability: кожен важливий компонент має автоматизовані тести.
- Recoverability: підтримка карантину та відновлення файлів, де це можливо.

### Цільова аудиторія

Користувачі macOS, яким потрібні інструменти для аналізу файлової системи, контролю дискового простору та безпечного обслуговування комп'ютера.

## 3. Функціональні модулі

### 3.1 Overview — Dashboard

Головний екран застосунку.

Функції:
- Загальний обсяг диска.
- Використаний і вільний простір.
- Результати останнього сканування.
- Кількість знайдених кандидатів на очищення.
- Потенційний обсяг звільнення.
- Стан системи.
- Швидкий доступ до основних інструментів.

### 3.2 System Junk

Пошук непотрібних файлів.

Категорії:
- User Cache.
- Application Cache.
- Temporary Files.
- Application Logs.
- Crash Reports.
- Застарілі тимчасові файли застосунків.
- Інші безпечні для аналізу категорії.

Вимоги:
- Не видаляти файли автоматично.
- Показувати повний шлях.
- Показувати розмір і категорію.
- Визначати рівень ризику.
- Давати можливість переглянути файл перед дією.
- Виключати системні та захищені каталоги.

### 3.3 Disk Analyzer

Аналіз використання дискового простору.

Функції:
- Аналіз директорій.
- Розмір каталогів.
- Візуалізація використання диска.
- Ієрархічне дерево директорій.
- Сортування за розміром.
- Перехід до каталогу у Finder.
- Пошук найбільших директорій.

### 3.4 Duplicates

Пошук дублікатів.

Алгоритм:
1. Сканування файлів.
2. Групування за розміром.
3. Попереднє порівняння кандидатів.
4. Обчислення SHA-256 для відповідних груп.
5. Формування груп однакових файлів.
6. Відображення результатів.

Вимоги:
- Не видаляти оригінали автоматично.
- Показувати всі шляхи.
- Дозволяти ручний вибір.
- Враховувати hard links та symlinks.
- Не вважати однаковий розмір достатнім доказом дубліката.

### 3.5 Large Files

Пошук великих файлів.

Функції:
- Пошук за мінімальним розміром.
- Фільтри за типами файлів.
- Сортування за розміром.
- Пошук у вибраних каталогах.
- Перегляд дати зміни.
- Відкриття у Finder.

### 3.6 Applications

Аналіз встановлених застосунків.

Функції:
- Список застосунків.
- Розмір застосунків.
- Основні відомості.
- Виявлення пов'язаних файлів.
- Пошук залишкових файлів.
- Перегляд пов'язаних каталогів.

Видалення застосунків та їхніх компонентів не повинно виконуватися без окремого підтвердження.

### 3.7 Privacy

Інструменти аналізу приватності.

Можливості:
- Перегляд локальних категорій даних, які користувач обрав для аналізу.
- Пошук тимчасових даних браузерів.
- Аналіз локальних журналів.
- Виявлення зайвих залишкових файлів.

Не читати приватний вміст повідомлень, пошти або браузерних профілів без окремої чіткої функціональної необхідності та дозволу.

### 3.8 Startup Manager

Аналіз елементів автозапуску.

Функції:
- Перегляд доступних login items.
- Відображення джерела запуску.
- Інформація про застосунок.
- Можливість відкрити відповідні системні налаштування.

Зміни елементів автозапуску — тільки після підтвердження.

### 3.9 System Monitor

Моніторинг системних показників.

Функції:
- CPU usage.
- RAM usage.
- Disk usage.
- Активність процесів.
- Основні системні показники.

Використовувати `psutil` та перевірені системні API.

### 3.10 Time Machine

Інформаційний модуль для роботи з Time Machine.

Функції:
- Визначення доступності резервного копіювання.
- Інформація про призначення резервних копій.
- Статус останнього резервного копіювання, якщо доступний.
- Перехід до системних налаштувань.

Видалення резервних копій і snapshots не входить до MacClear 1.0.

### 3.11 Maintenance

Безпечні операції обслуговування.

Можливості:
- Перевірка доступного дискового простору.
- Перегляд стану дозволів.
- Інформація про системні каталоги.
- Перевірка доступності основних компонентів.
- Формування системного звіту.

### 3.12 Settings

Налаштування застосунку.

Функції:
- Темна та світла тема.
- Мова інтерфейсу.
- Ignore List.
- Налаштування сканування.
- Максимальний розмір результатів.
- Налаштування журналу.
- Керування історією.
- Інформація про дозволи.
- Інформація про версію.

## 4. Архітектура застосунку

Використовувати багатошарову архітектуру з чітким розділенням відповідальності.

### 4.1 Presentation Layer

Відповідає за інтерфейс користувача.

Технології:
- PySide6.
- Qt Widgets.
- Qt Model/View.
- Qt Signals/Slots.

Не повинна містити логіку сканування, хешування або видалення файлів.

### 4.2 Application Layer

Керує сценаріями використання.

Приклади:
- ScanService.
- CleanupService.
- DiskService.
- DuplicateService.
- ReportService.

Визначає послідовність виконання операцій і взаємодію між компонентами.

### 4.3 Domain Layer

Містить основні моделі та правила застосунку.

Приклади:
- FileItem.
- ScanResult.
- DuplicateGroup.
- CleanupCandidate.
- OperationResult.
- SafetyPolicy.
- ExclusionPolicy.

Цей шар не повинен залежати від GUI або конкретного файлового API.

### 4.4 Infrastructure Layer

Реалізує роботу із зовнішніми ресурсами.

Компоненти:
- Filesystem.
- File metadata.
- File hashing.
- SQLite.
- macOS APIs.
- Logging.
- Permissions.

## 6. Безпека файлових операцій

Безпека є критичною частиною MacClear.

### 6.1 SafetyManager

Центральний компонент перевірки безпеки операцій.

Обов'язки:
- Перевіряти дозволені шляхи.
- Визначати системні та захищені каталоги.
- Перевіряти права доступу.
- Виявляти symlinks.
- Перевіряти тип файлового об'єкта.
- Не дозволяти вихід за межі дозволених директорій.
- Перевіряти стан файлу перед операцією.
- Перевіряти, чи змінився файл після сканування.
- Фіксувати результати операцій.

### 6.2 Рівні ризику

| Рівень | Значення | Дозволена дія |
|---|---|---|
| LOW | Низький ризик | Можна запропонувати очищення |
| MEDIUM | Потрібна додаткова увага | Попередження та підтвердження |
| HIGH | Високий ризик | Заборонити звичайне очищення |
| BLOCKED | Захищений об'єкт | Заборонити операцію |

HIGH і BLOCKED не повинні обходитися звичайним підтвердженням користувача.

### 6.3 Перевірки перед видаленням

Перед кожною операцією:
1. Перевірити, що шлях існує.
2. Перевірити тип об'єкта.
3. Перевірити, що шлях не є небезпечним symlink.
4. Перевірити, що об'єкт не належить до захищеної категорії.
5. Повторно перевірити метадані.
6. Переконатися, що файл не змінився після сканування.
7. Перевірити доступність операції.
8. Записати операцію в журнал.

Не покладатися лише на попередньо отримані шляхи. Уникати TOCTOU-помилок, де це можливо, використовуючи безпечні файлові операції та повторну перевірку об'єкта безпосередньо перед дією.

### 6.4 Ignore List

Користувач повинен мати можливість виключити:
- Окремі файли.
- Каталоги.
- Типи файлів.
- Категорії сканування.

Ignore List не повинен дозволяти користувачеві випадково відкрити доступ до системних об'єктів, які політика безпеки забороняє змінювати.

## 7. Quarantine та видалення

Передбачити три типи операцій.

### Quarantine

- Переміщення об'єкта до карантину.
- Збереження початкового шляху.
- Збереження метаданих.
- Можливість відновлення.
- Перевірка конфліктів при відновленні.

### Trash

- Переміщення до системного кошика macOS.
- Підтримка відповідної системної поведінки.
- Обробка помилок доступу та переміщення.

### Permanent Delete

- Окрема дія.
- Окреме підтвердження.
- Недоступна для системних і високоризикових об'єктів.
- Не є стандартним способом очищення.

### Важливі обмеження

- Не перезаписувати оригінали.
- Не обіцяти відновлення, якщо воно технічно неможливе.
- Враховувати різні томи та файлові системи.
- Враховувати APFS clones та snapshots.
- Не вважати переміщення в карантин гарантією звільнення фізичного простору.
- Перед відновленням перевіряти, чи не з'явився файл з таким самим ім'ям.

## 8. Дозволи macOS

MacClear повинен коректно працювати з механізмами захисту macOS.

### PermissionManager

Функції:
- Визначення доступності каталогів.
- Перевірка помилок доступу.
- Пояснення обмежень користувачеві.
- Підказки щодо системних налаштувань.
- Робота з доступними каталогами без Full Disk Access.
- Відображення статусу дозволів.

### Full Disk Access

Застосунок не може самостійно надати собі Full Disk Access.

Користувач повинен керувати цим дозволом у системних налаштуваннях macOS.

Не робити Full Disk Access обов'язковою умовою запуску MacClear.

### Додатково перевірити

- TCC.
- Sandbox.
- Security-scoped bookmarks.
- Доступ до Desktop, Documents, Downloads.
- Доступ до зовнішніх дисків.
- Поведінку дозволів після оновлення застосунку.
- Актуальні зміни політики Full Disk Access.

## 9. База даних SQLite

SQLite використовується для локального збереження налаштувань, історії та результатів операцій.

### Основні таблиці

| Таблиця | Призначення |
|---|---|
| scan_sessions | Сесії сканування |
| scan_results | Результати сканування |
| cleanup_history | Історія очищення |
| quarantine_items | Об'єкти карантину |
| excluded_paths | Ignore List |
| settings | Налаштування |
| system_reports | Системні звіти |

### Вимоги

- Використовувати параметризовані SQL-запити.
- Застосовувати транзакції.
- Передбачити індекси для частих запитів.
- Не зберігати всі шляхи безстроково без потреби.
- Передбачити очищення застарілих записів.
- Враховувати міграції схеми бази даних.
- Обробляти пошкодження або недоступність бази.

## 10. Продуктивність

MacClear не повинен блокувати GUI під час сканування.

### Вимоги

- Фонове виконання сканування.
- Фонове хешування.
- Можливість скасувати операцію.
- Показ прогресу.
- Передача результатів порціями.
- Контроль споживання RAM.
- Обробка великої кількості файлів.
- Уникнення зайвого повторного читання файлів.
- Поступове оновлення інтерфейсу.

Для фонових задач використовувати Qt-механізми, наприклад QThread або QRunnable, з коректною взаємодією через Signals/Slots.

### Оптимізація пошуку дублікатів

Не хешувати весь диск без потреби.

Спочатку групувати файли за розміром. Хешування виконувати лише для груп, у яких потенційно можуть бути дублікати.

## 15. Правила розробки

### Модульність

- Не створювати великі файли з різнорідною логікою.
- Не накопичувати бізнес-логіку в MainWindow.
- Кожен сервіс повинен мати чітку відповідальність.
- UI не повинен безпосередньо виконувати файлові операції.
- Повторювану логіку виносити в окремі компоненти.
- Не створювати абстракції без практичної потреби.

### Послідовність роботи

Для кожного модуля:

1. Визначити призначення.
2. Пояснити технології та бібліотеки.
3. Визначити інтерфейс модуля.
4. Реалізувати невеликий обсяг коду.
5. Написати тести.
6. Запустити тести.
7. Перевірити інтеграцію.
8. Оновити документацію.
9. Зафіксувати результат.
10. Перейти до наступного модуля.

### Якість коду

- Python type hints.
- Docstrings для публічних класів і функцій.
- Відповідальність класу має бути обмеженою.
- Обробка винятків на відповідному рівні.
- Не приховувати помилки порожніми `except`.
- Не дублювати логіку.
- Використовувати pathlib для роботи зі шляхами.
- Писати тести для критичних правил безпеки.

### Залежності

Не встановлювати всі бібліотеки на початку.

Додавати залежності тоді, коли вони потрібні конкретному модулю. Для кожної нової бібліотеки визначати:
- Навіщо вона потрібна.
- Яку проблему вирішує.
- Чи є стандартна бібліотека Python альтернативою.
- Які має обмеження.
- Чи підтримує цільові версії macOS та Apple Silicon.
